# Inkforge 使用说明

面向长篇连载的小说创作工作台。核心思路：**把「设定」从正文里抽出来做成事实源，让每一章在写的时候就对着事实源核对**，而不是等写完三百万字才发现主角的眼睛颜色变了。

- 单机运行，数据全在本机（SQLite 文件）
- 支持中文 / 英文界面切换
- AI 是可选增强：不配 AI 也能正常写、正常检查；配了才有「AI 起草」「AI 审稿」「AI 反推旧稿」

---

## 1. 三分钟上手

| 步骤 | 做什么 | 在哪 |
| --- | --- | --- |
| ① | 新建作品，填书名，题材可留空 | 侧栏「+ 新建作品」 |
| ② | 已有旧稿就导入；没有就直接新建章节开始写 | 侧栏「导入旧稿」/「+ 新建章节」 |
| ③ | 每写完一章，点「▶ 检查本章」，把阻断项改掉，再「定稿」 | 章节头部 |

如果这本小说已经写了很多：先做第 ④ 步——进「事实源 → AI 反推」，让 AI 从旧稿里读出角色、伏笔、世界规则，你勾选确认后写入事实源。之后新写的章节就有得可对了。

## 2. 界面地图

整个应用只有两个层级：**书房（书架）** 和 **工作台（一本书）**。

```
┌─────────────┬────────────────────────────────────────────────┐
│  书房        │  顶栏：返回 / 书名 / 搜索 / 语言 / 新建          │
│  ├ 作品列表  ├────────────────────────────────────────────────┤
│  └─────────  │  标签页：正文与章纲 │ 检查报告 │ 事实源 │ 全书检索 │
│             │                                                │
│  工作台      │  ┌──────────┬──────────────────┬───────────┐  │
│  ├ 卷章树    │  │ 左：卷章  │ 中：正文与章纲    │ 右：AI 起草│  │
│  ├ 新建章节  │  │ 拖拽排序  │ 写、存、定稿      │ 线索任务   │  │
│  ├ 导入旧稿  │  │          │                  │ 章纲声明   │  │
│  ├ 导出      │  └──────────┴──────────────────┴───────────┘  │
│  └ 设置      │                                                │
└─────────────┴────────────────────────────────────────────────┘
```

**左栏（工作台）**：按卷分组列出章节，可直接拖动改顺序（只支持同卷内拖动；跨卷请用「章节设置」改归属）。底部是导出与设置入口。

**顶栏四个标签页**：

| 标签 | 用途 | 什么时候看 |
| --- | --- | --- |
| 正文与章纲 | 写正文；右侧面板声明本章要写什么 | 写作时 |
| 检查报告 | 门禁 + 事实源审计 + AI 审稿的结果 | 写完一章后 |
| 事实源 | 角色、伏笔、规则、时间线、资源、大纲、快照 | 设定维护、反推旧稿 |
| 全书检索 | 关键词 + 向量混合检索全文 | 找「那句话在第几章」 |

**侧栏底部四个按钮**：`▶ 运行检查`、`⚙ AI 设置`、`💾 备份书库`、`📁 数据目录`。

## 3. 标准工作流：从旧稿到定稿

这一节是全书最该看的部分，按顺序做完就是完整闭环。

### 3.1 建书

侧栏「+ 新建作品」→ 填书名。**题材**建议选一个（玄幻 / 仙侠 / 悬疑 / 都市 / 恐怖 / 通用）：它不是装饰，会决定门禁与审计的松紧。比如「悬疑」会把「伏笔逾期」提到阻断级，「玄幻」会把「能力越界」提到阻断级。选错随时能在「作品设置」里换，已写入的世界规则会保留。

### 3.2 导入已有旧稿（可选）

「导入旧稿」支持三种入口：

- **选择文件…**：TXT / Markdown 单文件
- **选 Obsidian 仓库…**：整个文件夹，每个 `.md` 视为一章
- **直接粘贴**：把整本旧稿贴进文本框

拆章规则：识别「第 N 章」「Chapter N」「# 标题」这三种形式；文件内部已有章节标题会继续二次拆分。导入**只追加正文，绝不覆盖**现有章节，所以可以分批导入。

导入时会让你选归入哪个卷，也可以选「不归入卷」。确认前有预览，能看清章节数、总字数、前 40 章标题。

### 3.3 配 AI（可选，但强烈建议）

`⚙ AI 设置` 三步：

1. **加模型**：名称（随便起，如「本地 Qwen」）、协议、`base_url`、模型名。
   - Ollama 本地：协议选「OpenAI 兼容」，`base_url` 填 `http://localhost:11434/v1`，模型名填 `ollama list` 里看到的名字（如 `qwen2.5:14b`）
   - DeepSeek / 其他云服务：`base_url` 填对方给的地址，API Key 填进去
2. **测试连接**：点一下，绿色的 `✓ xxms` 就是通了
3. **用途分配**：写作 / AI 审稿 / 大纲建议 / Embedding 各自指定用哪个模型。**没指定的用途等于关闭**——比如没给 Embedding 指定模型，全书检索会自动退化为纯关键词检索，不会报错。

> **上下文窗口**这个字段要认真填。对本地 Ollama 模型，它会作为 `num_ctx` 真实生效；填太小会导致提示词被从头截断，而系统指令恰好在最前面——表现就是「AI 完全不听指令」。14B 模型建议至少 `8192`。

密钥经系统加密后单独存放，配置文件里只有引用 id，不会明文落盘。如果系统加密不可用（顶栏会标红），应用会拒绝保存密钥。

### 3.4 反推事实源（旧稿必备）

「事实源 → AI 反推」：

1. 设「抽样章数」（默认 8）。抽样策略是保留开头 3 章建立世界观、其余均匀抽样、每章截断 3500 字——这样百万字也不会把上下文撑爆
2. 点「开始反推」，等结果
3. 核对候选清单：角色、伏笔、世界规则会被默认勾选，**时间线默认不勾**（AI 推断的时间线噪声较大，建议手工补）
4. 标了「已在事实源」的条目会被自动跳过，不会重复写入
5. 点「采纳所选并写入事实源」

反推是**只读正文**的：它不会改你已写的正文，也不会覆盖已有事实条目。有疑问就去对应页面手工改。

### 3.5 逐章写

进「正文与章纲」，中间是编辑器，右边三块：

- **AI 起草**：填「额外指导」（本章重点、口吻），点「生成新稿」。生成完不会直接覆盖正文，而是弹出逐段裁决——你一段段选「采用 / 保留原文」，最后才写入。生成过程可随时「取消」。
- **本章线索任务**：从事实源算出来的「这一章应该推进/回收哪个伏笔」，附证据词要求。
- **章纲声明**：目标字数、Strand 节奏（主线 Quest / 感情线 Fire / 世界观 Constellation）、钩子类型（悬念断崖 / 揭示 …）、出场角色、情绪标签。

**章纲声明不是填给 AI 看的装饰**，检查报告会核对你声明的东西有没有真的出现在正文里。

写的时候：`Ctrl / ⌘ + S` 保存草稿；想标记完成就点「定稿」。定稿会生成一份不可变收据（收在「事实源 → 大纲·分卷·收据」里），之后正文若被替换，旧收据会标 `superseded`。

### 3.6 运行检查，读懂报告

点「▶ 检查本章」（或侧栏「▶ 运行检查」）。报告分三层，**责任边界不同**：

| 层 | 谁在判 | 能不能阻断定稿 |
| --- | --- | --- |
| 门禁 | 本地确定性脚本（字数、伏笔证据词、钩子轮换、重复用语…） | 能。阻断项不改就定不了稿 |
| 事实源审计 | 本地事实核对（人物是否已故、能力是否越界、地点是否瞬移…） | 报 `error` 级时按阻断处理，其余为提示 |
| AI 审稿 | 大模型判断（人物一致性、逻辑合理性、文风自然度、情感弧线） | **不能**。只做观察，不参与阻断 |

这条边界是刻意的：确定性规则才允许拦住你，AI 的看法只当参考。所以「AI 审稿」要单独点（报告里有按钮），不会跟着门禁一起跑。

改动阻断项 → 重新检查 → 变绿 → 定稿。

### 3.7 导出

侧栏底部三种：

| 方式 | 内容 | 用途 |
| --- | --- | --- |
| 导出 TXT | 卷/章标题 + 正文 | 直接投稿 |
| 导出 MD | 同上，Markdown 格式，跳过空章 | 阅读、发平台 |
| 导出归档版 | 额外附带事实源表格 | 备份、给别人交接 |

也可以只导一章：编辑器右上「导出本章 MD」。

## 4. 事实源：六个子页

事实源是这本小说的**唯一事实来源**。改设定只改这里，不要靠正文里记。

### 角色

姓名、别名、当前所在地、能力/境界、已知信息、备注、是否存活。

「**生效章**」是关键概念：角色状态按生效章取值，补写中间章不会读到后文的状态。所以你可以放心回头补写第 5 章的伏笔，而不用担心读到第 30 章的结局。

每行右侧的「来源」会告诉你这条状态是**作者手写（author）**、还是**从正文派生（derived）**、还是**旧数据迁移（legacy）**——派生状态在正文被替换后可能标 `stale`，看到就说明该复核了。

### 伏笔

伏笔账本，每条有类型（主线/支线）、状态、埋设章、计划回收章、回收证据词。

三条纪律：

1. **回收必须有正文证据词**，且必须真的出现在正文里，否则门禁拦你
2. 状态流转只有三条路：`埋设 → 推进 → 回收`，或 `放弃`
3. 顶部要先选「操作生效章」，之后点「推进 / 回收 / 放弃」才有章号可记

### 规则·时间线·资源

- **世界规则**：分类 + 规则内容 + 优先级。优先级 `≥100` 是铁律，会**无条件注入**给 AI，不能违反
- **时间线**：故事顺序、故事时间（如「第三年·秋」）、事件描述、关联章
- **资源**：名称、分类、持有者、数量、备注

### 大纲·分卷·收据

- **作品总纲**：写前事实，AI 起草时会和卷纲、章纲一起注入。右侧「AI 生成卷纲建议」只把结果填进文本框，**必须你自己点保存**才生效
- **卷纲**：本卷目标、关键转折、卷末钩子
- **定稿收据**：每次定稿一张不可变收据。`当前有效` / `已被替换` 一眼能看出哪版是准的

### 状态快照

只存事实、不复制正文的快照。

「回退到此快照」有个重要限制：**只回退结构化事实源状态，正文一个字都不动**。因为它会先给你一份预览——字段级状态差异 + 正文中可能冲突的段落——你确认后才执行。冲突段落需要你人工处理，已定稿的正文要手动改并重新定稿。

这个设计是为了不出现「事实回退了、正文还是新的」这种静默不一致。

### AI 反推

见 3.4。

## 5. 全书检索

支持三种模式，自动选择：

- 配了 Embedding 模型 → **混合检索**（关键词 + 向量）
- 没配 → **纯 BM25**（页面会提示「检索退化为 BM25」）
- 每个结果会显示分数来源：`综合` / `向量`

「重建向量索引」在换 Embedding 模型后点一次，会告诉你新索引多少章、跳过多少章、失败多少章。

## 6. 数据、备份、恢复

**数据目录**：`%APPDATA%\inkforge-core\workbench\`

```
inkforge.db        ← 全部作品、章节、事实源（SQLite）
inkforge.db-wal    ← 事务日志
ai-config.json     ← 模型配置（不含明文密钥）
backups/           ← 手动备份落点
```

**备份**：侧栏 `💾 备份书库`，或菜单「文件 → 备份书库」。生成带时间戳的快照文件，提示里会给出文件大小和文件名。

**恢复**：先「文件 → 退出」，把 `backups/` 里的目标文件复制回 `workbench/` 并改名 `inkforge.db`，删掉旁边的 `-wal` / `-shm`，再启动。

**换机器**：整目录拷走 `workbench/` 即可。注意密钥是系统加密的，换机器后要重填 API Key。

**误删作品**无法撤销——删除确认框里已经写明「会删除全部章节、事实源、快照与检索索引」。这也是为什么建议开工前先备份一次。

## 8. 常见问题

**AI 完全不听指令，回复跑偏或只有半截**
八成是上下文窗口太小。Ollama 的原生接口会按 `num_ctx` 从开头截断，系统指令在最前面，最先被丢掉。把「AI 设置 → 上下文窗口」调到 8192 以上。

**AI 反推回来 0 条**
先确认「测试连接」是绿的；再确认模型有足够上下文装下抽样内容；换更大的模型重试。

**检索结果很少**
没配 Embedding 模型时会退化成纯 BM25，只能匹配字面关键词。想语义检索就去配一个 Embedding 用途的模型，然后「重建向量索引」。

**定不了稿，说有阻断项**
回「检查报告」看红的那几条，都是本地确定性规则（字数为 0、伏笔声明回收但正文没有证据词、钩子类型连续重复…）。改完重新检查即可。

**导入拆章不对**
拆章只认「第 N 章」「Chapter N」「# 标题」。格式特殊的话，先规范化标题行再导入，或者在编辑器里手动新建章节、粘贴正文。

**拖动章节没反应**
只支持同卷内拖动。跨卷请在「章节设置」里改归属。

**换了题材，会不会覆盖我写的规则**
不会。应用题材只补充不覆盖，可以重复应用。清除题材也只是把门禁/审计侧重恢复默认，世界规则照旧保留（那是你的资产）。

## 9. 开发者：运行、测试、打包

```bash
pnpm install

pnpm dev        # 开发模式（HMR）
pnpm start      # 构建后启动，接近发布形态
pnpm gate       # 类型检查（tsc + vue-tsc）+ 全部单测
pnpm build      # electron-vite build
pnpm smoke      # 冒烟测试：主进程起得来、IPC 通
pnpm ui-audit   # CDP 驱动真实界面：点按钮、跑 IPC、验渲染
```

Windows 上还有 `一键启动 Inkforge.vbs`（无控制台窗口）和 `一键启动（显示日志）.bat`（带日志）。

架构分层与各层职责见 `README.md` 的目录说明。改动前先把 `pnpm gate` 跑绿，是这个仓库的约定。

## 10. 一条建议

先别急着开新书。**找一部你已经写了十几万字的旧稿，走一遍完整流程**：导入 → 反推事实源 → 检查 → 定稿 → 导出。

走完你会立刻知道这套工具在你的写作习惯里该摆在什么位置——多数人第一次用完会改掉的不是正文，而是「原来我上一章把主角写到城南去了」。
